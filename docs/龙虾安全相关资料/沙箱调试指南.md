# 沙箱工作区调试指南

## 📍 工作区位置总览

### 1. Hardened Profile 主工作区
**位置**：`~/.openclaw-hardened/workspace/`

这是安全版龙虾的**主工作区**，包含：
- `SOUL.md` - AI 人格和安全规则定义
- `MEMORY.md` - 记忆文件（使用环境变量引用）
- `AGENTS.md` - Agent 配置
- `IDENTITY.md` - 身份信息
- `TOOLS.md` - 工具说明
- `USER.md` - 用户信息
- `memory/` - 记忆数据库

```bash
# 查看工作区内容
ls -la ~/.openclaw-hardened/workspace/

# 编辑 SOUL.md（安全规则）
vim ~/.openclaw-hardened/workspace/SOUL.md

# 查看 MEMORY.md（应该使用 ${VAR} 引用）
cat ~/.openclaw-hardened/workspace/MEMORY.md
```

---

### 2. 沙箱容器工作区（临时）
**位置**：`~/.openclaw-hardened/sandboxes/`

每次会话都会在 `sandboxes/` 下创建一个**独立的沙箱目录**，每个沙箱容器挂载这个目录作为工作区。

```bash
# 查看所有沙箱会话
ls -la ~/.openclaw-hardened/sandboxes/

# 查看特定沙箱会话
ls -la ~/.openclaw-hardened/sandboxes/agent-main-openai-*/
```

**沙箱目录结构**：
```
~/.openclaw-hardened/sandboxes/
├── agent-main-openai-b030f195-e5e4--af92b726/  # 会话 1
│   ├── .openclaw/
│   ├── AGENTS.md
│   ├── SOUL.md
│   ├── MEMORY.md
│   └── ...
├── agent-main-openai-1eee9405-e6f2--1fcf6b81/  # 会话 2
└── ...
```

⚠️ **注意**：这些沙箱目录是临时的，会话结束后可能被清理。

---

### 3. Docker 容器内部工作区
**位置**：容器内的 `/home/sandbox/`

沙箱容器启动后，会挂载宿主机的沙箱目录到容器内。

```bash
# 查看运行中的沙箱容器
docker ps --filter "name=openclaw-sbx"

# 进入容器查看工作区
docker exec -it <container-id> ls -la /home/sandbox/

# 查看容器挂载信息
docker inspect <container-id> | grep -A 20 Mounts
```

### 网络配置说明

#### 当前网络模式

```json
{
  "sandbox": {
    "docker": {
      "network": "none"  // 当前配置
    }
  }
}
```

| 值 | 说明 | 安全等级 | URL 过滤 |
|---|---|---|---|
| `"none"` | **完全禁止网络访问** | 🔒 最安全 | ✅ 所有网址都无法访问 |
| `"bridge"` | 允许容器间通信 | ⚠️ 需网络时用 | ❌ 所有外网都可以访问 |
| `"host"` | 共享宿主机网络 | ❌ 危险 | ❌ 完全暴露 |

#### URL 白名单/黑名单支持

❌ **OpenClaw 原生不支持 URL 白名单或黑名单配置**

如果需要精细的网址控制，有以下方案：

**方案 1: 代理服务器 + 白名单（推荐）**
```json
{
  "sandbox": {
    "docker": {
      "network": "bridge",
      "env": {
        "HTTP_PROXY": "http://squid-proxy:3128",
        "HTTPS_PROXY": "http://squid-proxy:3128"
      }
    }
  }
}
```
然后在 Squid 代理中配置 ACL：
```
# Squid 配置示例
acl allowed_sites dstdomain .github.com .api.openai.com
http_access allow allowed_sites
http_access deny all
```

**方案 2: 命令白名单限制网络工具**
```json
{
  "tools": {
    "exec": {
      "safeBins": [
        "ls", "grep", "cat", "head", "tail",
        // ⚠️ 不包含 curl、wget 等网络工具
      ]
    }
  }
}
```

**方案 3: Docker 内部网络 + 网关代理**
```bash
# 创建无外网的内部网络
docker network create --internal openclaw-internal

# 只允许访问特定的内部代理容器
# Agent → 内部代理 → 外部 API(代理控制白名单)
```

#### 沙箱浏览器网络配置

如果需要使用浏览器功能，可以单独配置浏览器网络：
```json
{
  "sandbox": {
    "browser": {
      "autoStart": true,
      "network": "openclaw-sandbox-browser",  // 专用 Docker 网络
      "cdpSourceRange": "172.21.0.1/32"       // 限制 CDP 访问来源
    }
  }
}
```

## 🐛 常见问题排查

### 问题 1：沙箱容器未创建
**症状**：发送消息后，`docker ps` 没有看到 `openclaw-sbx-*` 容器

**排查**：
```bash
# 1. 检查沙箱模式是否正确
cat ~/.openclaw-hardened/openclaw.json | python3 -c "
import sys,json
d=json.load(sys.stdin)
sb=d['agents']['defaults']['sandbox']
print(f'sandbox.mode: {sb[\"mode\"]}')
print(f'sandbox.scope: {sb[\"scope\"]}')
"

# 2. 检查沙箱镜像是否存在
docker images openclaw-sandbox:bookworm-slim

# 3. 查看 Gateway 日志
tail -100 /tmp/openclaw/openclaw-$(date +%Y-%m-%d).log | grep -i sandbox

# 4. 运行 sandbox explain
openclaw --profile hardened sandbox explain --json
```

**解决**：
- 确保 `sandbox.mode: "all"`
- 确保沙箱镜像已构建：`docker images openclaw-sandbox:bookworm-slim`
- 重启 Gateway：`openclaw --profile hardened gateway restart`

---

### 问题 2：沙箱容器无法执行命令
**症状**：Agent 回复"命令执行失败"或"权限拒绝"

**排查**：
```bash
# 1. 查看容器状态
docker ps --filter "name=openclaw-sbx"

# 2. 查看容器日志
docker logs <container-name> 2>&1 | tail -50

# 3. 检查容器内文件系统
docker exec <container-name> ls -la /home/sandbox/

# 4. 测试只读文件系统
docker exec <container-name> touch /test-file 2>&1
# 应该输出：Read-only file system

# 5. 测试临时目录可写
docker exec <container-name> touch /tmp/test && echo "✅ /tmp 可写"
```

**解决**：
- 沙箱根文件系统是只读的，只能写入 `/tmp`
- 检查命令是否在 `safeBins` 白名单中

---

### 问题 3：网络请求失败（预期行为）
**症状**：Agent 执行 curl 命令失败

**这是正常行为**！沙箱容器网络设置为 `none`，无法访问外部网络。

**验证**：
```bash
# 检查容器网络配置
docker inspect <container-name> | grep -A 5 NetworkMode
# 应该显示：\"NetworkMode\": \"none\"

# 在容器内测试网络
docker exec <container-name> ping -c 1 8.8.8.8 2>&1
# 应该失败
```

**如果需要网络**（调试时临时开启）：
```bash
# 修改配置（不推荐生产环境）
# 在 ~/.openclaw-hardened/openclaw.json 中：
"sandbox": {
  "docker": {
    "network": "bridge"  # 改为 bridge
  }
}

# 重启 Gateway
openclaw --profile hardened gateway restart
```

### 问题 4：MEMORY.md 修改不生效
**症状**：修改了 MEMORY.md，但 Agent 行为没有变化

**排查**：
```bash
# 1. 确认修改的是正确的文件
cat ~/.openclaw-hardened/workspace/MEMORY.md

# 2. 检查文件权限
ls -la ~/.openclaw-hardened/workspace/MEMORY.md

# 3. 重启 Gateway 加载新配置
```

**注意**：
- 修改 SOUL.md 或 MEMORY.md 后，需要**重启 Gateway** 并**开始新会话**
- 旧会话可能保留旧配置，不会自动更新

## 📦 沙箱 Workspace 初始化机制

### 核心概念：Seed（种子）机制

沙箱**不是每次都全新创建**，而是采用 **Seed 机制**从主 Workspace 初始化：

```
主 Workspace (~/.openclaw-hardened/workspace/)
    ↓ Seed（首次一次性复制）
沙箱目录 (~/.openclaw-hardened/sandboxes/<session-id>/)
    ↓ 挂载到 Docker 容器
容器内 /home/sandbox/
```

### 关键配置参数

在 `~/.openclaw-hardened/openclaw.json` 中：

```json
{
  "agents": {
    "defaults": {
      "workspace": "/Users/han/.openclaw-hardened/workspace",  // 主工作区路径
      "sandbox": {
        "mode": "all",              // 所有会话都使用沙箱
        "scope": "session",         // 每个会话独立容器
        "workspaceAccess": "ro",    // 🔑 关键！只读访问主 Workspace
        "docker": {
          "image": "openclaw-sandbox:bookworm-slim",
          "containerPrefix": "openclaw-sbx-",
          "network": "none",        // 完全禁止网络
          "readOnlyRoot": true      // 容器根文件系统只读
        }
      }
    }
  }
}
```

### workspaceAccess 参数详解

| 值 | 说明 | 安全性 | 持久化 |
|---|---|---|---|
| `"ro"` | **只读访问**主 Workspace | 🔒 最安全 | ❌ 沙箱修改不持久化 |
| `"rw"` | 读写访问主 Workspace | ⚠️ 有风险 | ✅ 沙箱修改会影响主文件 |

**你的当前配置**: `"workspaceAccess": "ro"` （只读）

### 初始化流程

#### 1️⃣ 首次 Seed（种子创建）

当首次启动 Gateway 或创建新会话时：

```bash
# 主 Workspace 的状态文件
cat ~/.openclaw-hardened/workspace/.openclaw/workspace-state.json
{
  "version": 1,
  "bootstrapSeededAt": "2026-05-14T01:42:20.720Z",  # ← 首次种子时间
  "setupCompletedAt": "2026-05-19T17:23:44.841Z"
}

# 沙箱的状态文件
cat ~/.openclaw-hardened/sandboxes/agent-main-openai-*/.openclaw/workspace-state.json
{
  "version": 1,
  "setupCompletedAt": "2026-05-20T10:25:58.637Z"  # ← 沙箱创建时间
}
```

#### 2️⃣ 复制的文件清单

从主 Workspace 复制到沙箱目录的文件：
- `SOUL.md` - AI 人格和安全规则
- `AGENTS.md` - Agent 配置
- `IDENTITY.md` - 身份信息
- `TOOLS.md` - 工具说明
- `USER.md` - 用户信息
- `HEARTBEAT.md` - 心跳文件
- `.openclaw/` - 配置目录
- `skills/` - 技能目录（如果有）

⚠️ **注意**: `MEMORY.md` **不会被复制**到沙箱（因为使用环境变量引用，不需要复制）

#### 3️⃣ Docker 容器挂载

容器启动时挂载沙箱目录：
```bash
# 容器内的路径
/home/sandbox/  →  宿主机 ~/.openclaw-hardened/sandboxes/<session-id>/

# 查看容器挂载信息
docker inspect <container-id> | grep -A 20 Mounts
```

### Workspace 持久化策略

#### 当前配置（workspaceAccess: "ro"）

```
主 Workspace (只读)
    ↓ 复制
沙箱目录 (可写，但不会同步回主目录)
    ↓ 容器销毁
所有修改丢失 ❌
```

**优点**：
- ✅ 沙箱无法修改主 Workspace 文件
- ✅ 每次会话都是干净的初始状态
- ✅ 防止恶意修改持久化

**缺点**：
- ❌ 沙箱内的修改不会保留
- ❌ 需要在主 Workspace 修改才能持久化

#### 如何持久化修改

**方式 1: 在主 Workspace 修改（推荐）**
```bash
# 1. 直接修改主 Workspace 文件
vim ~/.openclaw-hardened/workspace/SOUL.md

# 2. 重启 Gateway
openclaw --profile hardened gateway restart

# 3. 新会话会自动使用新配置
```

**方式 2: 手动从沙箱同步（临时调试）**
```bash
# 1. 从容器复制文件到主 Workspace
docker cp <container-id>:/home/sandbox/SOUL.md ~/.openclaw-hardened/workspace/SOUL.md

# 2. 重启 Gateway
openclaw --profile hardened gateway restart
```

**方式 3: 改为读写模式（不推荐，有风险）**
```json
{
  "sandbox": {
    "workspaceAccess": "rw"  // ⚠️ 沙箱可以直接修改主文件
  }
}
```

⚠️ **风险警告**: `"workspaceAccess": "rw"` 意味着沙箱内的恶意修改会直接影响主 Workspace！

### 重新 Seed 的方法

如果你想让所有沙箱重新从主 Workspace 同步：

```bash
# 方法 1: 使用 OpenClaw 命令（推荐）
openclaw --profile hardened sandbox recreate

# 方法 2: 手动删除旧沙箱，让 OpenClaw 自动重建
rm -rf ~/.openclaw-hardened/sandboxes/agent-main-openai-*

# 方法 3: 清理所有沙箱容器和目录
docker rm -f $(docker ps -aq --filter "name=openclaw-sbx") 2>/dev/null
rm -rf ~/.openclaw-hardened/sandboxes/*

# 然后重启 Gateway
openclaw --profile hardened gateway restart
```

### 对比不同后端的 Workspace 模型

| 后端 | Workspace 模型 | 说明 |
|---|---|---|
| `docker` | **Bind-mount 或 Copy** | 从主 Workspace 复制，可配置只读/读写 |
| `ssh` | **Remote-canonical** | 首次 Seed 后远程成为权威，不再同步 |
| `openshell` | **Mirror 或 Remote** | 支持双向同步或远程模式 |

### 验证 Workspace 初始化

```bash
# 1. 对比主 Workspace 和沙箱文件
diff ~/.openclaw-hardened/workspace/SOUL.md \
     ~/.openclaw-hardened/sandboxes/agent-main-openai-*/SOUL.md

# 2. 查看沙箱创建时间
stat ~/.openclaw-hardened/sandboxes/agent-main-openai-*/.openclaw/workspace-state.json

# 3. 检查沙箱目录结构
ls -la ~/.openclaw-hardened/sandboxes/agent-main-openai-*/

# 4. 确认文件一致性
md5sum ~/.openclaw-hardened/workspace/SOUL.md
md5sum ~/.openclaw-hardened/sandboxes/agent-main-openai-*/SOUL.md
```

### 沙箱后端对比

OpenClaw 支持多种沙箱后端，你当前使用的是 Docker 后端：

| 特性 | Docker (你的) | SSH | OpenShell |
|---|---|---|---|
| **运行位置** | 本地容器 | SSH 远程主机 | OpenShell 管理 |
| **设置方式** | `scripts/sandbox-setup.sh` | SSH 密钥 + 目标主机 | OpenShell 插件 |
| **Workspace 模型** | Bind-mount 或 Copy | Remote-canonical（首次 Seed） | Mirror 或 Remote |
| **网络控制** | `docker.network`（默认 none） | 依赖远程主机 | 依赖 OpenShell |
| **浏览器沙箱** | ✅ 支持 | ❌ 不支持 | ❌ 尚不支持 |
| **Bind mounts** | ✅ `docker.binds` | N/A | N/A |
| **适用场景** | 本地开发、完全隔离 | 远程机器卸载 | 管理的远程沙箱 |

### 你的沙箱配置总结

```json
{
  "backend": "docker",           // 使用 Docker 后端
  "mode": "all",                 // 所有会话都使用沙箱
  "scope": "session",            // 每个会话独立容器
  "workspaceAccess": "ro",       // 只读访问主 Workspace
  "network": "none",             // 完全禁止网络
  "readOnlyRoot": true,          // 容器根文件系统只读
  "image": "openclaw-sandbox:bookworm-slim"
}
```

**安全等级**: 🔒🔒🔒🔒🔒（最高）

**隔离效果**：
- ✅ 文件系统隔离：容器根只读，只能写 /tmp
- ✅ 网络隔离：完全禁止网络访问
- ✅ Workspace 保护：只读访问，无法修改主文件
- ✅ 会话隔离：每个会话独立容器
- ✅ 资源限制：可配置 CPU 和内存限制

## 💡 调试技巧

1. **使用 `sandbox explain`** 查看实际生效的配置
2. **查看容器日志** 了解沙箱执行细节
3. **进入容器调试** 直接测试文件系统和网络
4. **对比 Naked 和 Hardened** 的配置差异
5. **每次修改配置后重启 Gateway** 并创建新会话
6. **查看 workspace-state.json** 了解 Seed 时间
7. **使用 `diff` 命令** 对比主 Workspace 和沙箱文件的差异
8. **修改主 Workspace 文件** 而非沙箱文件，确保修改持久化
9. **使用 `sandbox recreate`** 重新从主 Workspace 同步沙箱
10. **检查 workspaceAccess 配置** 确认是 ro（只读）还是 rw（读写）
